# 文档归档维护规则

用户于 2026-10-11 要求：每次为本项目交互生成的 XMind、Markdown 等文档，都上传一份到本仓库，分类并标注日期。此要求适用于后续文档交付，已有用户上传授权，不需要逐次重问。

- 分类：plans（方案）、research（调研）、acceptance（执行与验收）、technical（技术说明）、mindmaps（思维导图及配套预览）、reference（清单）。
- 路径：分类/YYYY-MM-DD/文件名-日期-版本。日期采用 Asia/Shanghai；原日期未知时使用快照日期并明示。
- 遵循本目录 README 的分类、日期、版本及索引规则；同日新修订新增版本，不覆盖已交付版本。
- 仅归档本项目交互产物；不上传凭据、.env、真实农场私密数据、完整代码快照和运行缓存。
- 每次核验文件、相对链接、同版附件及 SHA256，区分原文日期与归档日期。
- 文档上传与业务代码发布分开；不将本地测试记录宣称为线上通过。
- 核验目标仓库、分支、远端文件与提交后才称上传成功；失败则保存待上传清单和原因。

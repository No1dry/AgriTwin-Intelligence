# 外部情报采集与简报技术说明

日期：2026-10-13（Asia/Shanghai）。版本：v1。

## 交付范围

本阶段独立完成外部来源采集、官方 Kimi 摘要、可溯源简报和 GitHub Pages 展示。原调研 16 组外部来源全部配置真实采集适配，另增 Open-Meteo 区域天气。注册数量不是接通数量，逐源实测结果见同日验收记录。

内部农场、ontology、田塘、作物批次和传感器未接入，数据协议的 `internal` 为 null，页面显示 N/A。地图中心是梁子湖区地理范围推算中点，不是农场位置；没有绘制虚构地块或风险点。

## 真实来源如何使用

HTML 来源先检查 robots，再读取列表和有限详情页。每组通常最多两篇，每来源最多六次请求，来源并发最多三。中央气象台使用已核实的周报正文节点，FAO 使用实际稻渔章节；导航、目录和没有正文的页面不作为成功文章。

arXiv 收录预印本摘要，OpenAlex 收录索引摘要，GitHub 收录农业工具元数据；这些状态不等于同行评审、开源许可已核验或工具已运行。附件和图片没有转成正文时明确标注。历史资料保留原日期或未知日期，不改成今日新闻。

Open-Meteo 是气象模型网格数据，包含区域当前模型值与三日预报；官方预警仍依赖未配置的 QWeather 凭据。天气和卫星影像不作为田塘实测。Esri 底图保留署名，影像不是实时，也不提供本轮已知拍摄日期。

## 摘要与证据

模型输入为每篇标题和正文前 620 个 Unicode 字符，优先覆盖不同来源，再补充同源条目。每次最多六篇、每轮最多三次请求；每次最多输出 1024 tokens，关闭 thinking，无自动重试。

首轮实测发现重新抄写引文会发生逐字校验失败。修复后，程序从模型输入提取原文片段并赋予 `q1/q2` 编号，模型输出中文摘要和片段编号，程序绑定原文及 URL。编号越界、错文章 ID、重复/缺少条目或异常摘要被拒绝。旧逐字引用校验仍保留兼容，但新提示使用编号协议。

公开文章仅包含前 180 字短摘。证据片段可能来自第 181–620 字范围，因此前端不要求引文出现在公开短摘内；后端仍针对实际模型输入校验。证据绑定检查不能证明摘要语义正确，页面保留“待专业审核”。

模型调用失败保留真实状态与已知用量，不伪造成功摘要。缺失任何已发请求的用量时，完整用量显示未知。单轮调用次数上限不是固定金额预算；输入 tokens 也计费。

## 输出和展示

`public/external/latest.json` 的 `meta` 记录生成时间、数据时点和模型运行状态；`sources` 记录每源结果，`articles` 记录正文短摘、哈希、发布时间精度和摘要；`modelRun` 记录实际 Actions URL、调用次数及 tokens；`weather` 是区域模型天气；`internal` 固定 null。

公开输出校验、写入完成后才设置本轮发布标记。模型整体失败时可发布有效失败诊断，同时保留工作流失败信号；没有本轮有效结果则不提交旧文件。全量正文缓存不属于公开发布内容。

独立 Showcase 仓库发布四份静态文件。浏览器优先读取引擎最新公开 JSON，失败时使用站内快照并显示时间。左栏用于发现和筛选，中间提供梁子湖区域位置语境，右栏呈现摘要、原文与限制；底部可核对真实模型调用和用量。“加入简报”是当前会话内选编，“生成简报”打开 Actions 手动运行入口。

## 配置位置

Actions：Settings → Secrets and variables → Actions。必需 `MOONSHOT_API_KEY`。可选 `OPENALEX_API_KEY`。QWeather 需要 `QWEATHER_API_HOST` 加 `QWEATHER_API_KEY` 或 `QWEATHER_JWT`。

本地模板：`config/external.env.example`，值为空。复制到根目录 `.env.kimi.local`，用 Node 的 `--env-file=.env.kimi.local` 显式加载。Pages 不配置模型密钥。

当前仅手动实测。下一阶段优先修复仍受阻的来源、正文/附件提取与跨日增量，再配置运行频率；内部关联待 ontology 与农场接口就绪后通过稳定对象标识接入。
